# pair-wise-yf-55 动态表单规则编排和版本迁移模拟器

## 源提示词摘要
业务人员拖拽字段、设置分组、联动条件、计算规则、必填逻辑和多语言文案；发布前模拟旧数据在新结构下的迁移。系统比较版本差异，警告失效规则、循环依赖和引用删除，同时按历史版本解释过去提交的数据。

## 技术栈
React 19 + TypeScript + Vite + MUI + Redux Toolkit + React Hook Form + Zod + i18next + dnd-kit。

## 标识（key）与显示名称（label）分离
- 每个字段有稳定身份 `uid`、对外字段标识 `key`、可随时改的显示名称 `label`。
- 改名称只动 `label`，标识照旧，历史数据不受影响；差异面板把“仅改名”和“换标识”分成两类展示。
- 真要换标识走「更换标识…」：登记一条 `oldKey → newKey` 对照，完成后字段才换新标识；没做完的对照持久化在草稿里，保存中断、关掉页面重开还能接着处理或取消。
- 完成对照的同时，所有引用旧标识的联动规则（源/目标）自动重算到新标识，界面列出受影响的规则编号。

## 发布冻结与历史解释
- 发布即生成不可变版本快照（`frozenAt` 冻结点）：字段标识、规则、对照全部冻结，以后再改名/换标识都不改旧版本。
- 历史记录带 `versionId`，永远按“填写当时那一版”的名称和标识解释。
- 旧数据兼容读回：从记录所在版本到目标版本，沿各版本冻结的对照链逐跳翻译（支持 `amount → totalAmount → money` 多跳），被删字段的值搁置提示，缺必填会列出。

## 发布前校验（撞车必须停下并指出条目）
- 同一版两个字段用到同一标识：报出具体是哪几个字段。
- 两条待处理对照换到同一个新标识：报出是哪两条对照（如 p1 与 p2）。
- 新标识和已有标识撞车：报出与哪个字段冲突。
- 还存在没做完的对照：阻止发布（对照保留，可继续处理）。
- 联动引用了已不存在的标识：警告，发布冻结时自动剔除该联动。

## 两个标签页并发发布
- 每份草稿记录基线版本号 `baselineRevision`；发布时若发现最新版本已不是基线（另一标签页先发布），发布被拦下。
- 草稿完整保留并三方合并到最新基线（草稿改动优先、新版本新增内容并入），提示“重新比对”后再发布。
- 状态通过 `localStorage` + `storage` 事件在标签页间同步；页内可点「复制并行草稿」模拟并发。

## 已实现闭环
- 字段显示名称/类型/必填就地编辑、拖拽排序、添加字段、标识对照登记（半成品可续做）。
- 联动规则增删、按标识引用、换标识自动重算、悬空引用警告。
- 版本差异（新增/删除/仅改名/换标识/排序/规则差异）、旧数据迁移模拟。
- 运行态动态表单（show/require 联动、动态必填），提交按冻结标识存档。
- 版本与历史记录按当时版本解释；localStorage 持久化。
